# 系统升级说明 - 废弃购买意向功能

## 📅 变更日期
2025年12月4日

---

## ⚠️ 重要变更

### 已废弃功能
**购买意向系统 (purchase_intents)** 已完全废弃并移除

---

## 🔄 变更原因

### 旧系统问题
购买意向系统存在以下限制：
1. **非真实交易**：仅记录客户想买什么，不涉及实际库存扣减
2. **缺乏流程管理**：没有订单状态流转（确认→备货→发货→完成）
3. **功能简陋**：不支持多商品下单、购物车、收藏等电商基本功能
4. **商家无控制权**：只能查看意向，无法管理订单生命周期

### 新系统优势
升级为完整的**订单管理系统 (orders)**：
- ✅ 真实交易流程，下单即扣减库存
- ✅ 5个订单状态流转（PENDING→CONFIRMED→PREPARING→SHIPPING→COMPLETED）
- ✅ 完善的订单取消机制（客户/商家权限控制，自动恢复库存）
- ✅ 支持购物车批量下单
- ✅ 支持商品收藏功能
- ✅ 记录订单详情、收货信息、商品明细

## 📝 已修改文件

### 前端文件修改

#### 1. OrderManagement.vue（完全重写）
**旧功能**：显示购买意向列表，支持完成/取消
**新功能**：
- 显示订单列表，支持按状态筛选（待确认/待备货/待发货/已发货/已完成/已取消）
- 商家可进行订单状态流转：确认订单→备货完成→开始发货→完成交易
- 商家可取消订单并填写取消原因
- 查看订单详情（订单编号、收货人、地址、商品明细等）

#### 2. SellerDashboard.vue
**修改内容**：订单统计改为调用 `/api/seller/orders` 接口
- 待处理订单数：状态为 PENDING/CONFIRMED/PREPARING/SHIPPING 的订单数量
- 已完成订单数：状态为 COMPLETED 的订单数量

#### 3. router.js
**删除内容**：
- `import PurchaseForm` 语句
- `/product/:id/purchase` 路由配置

## 🔄 迁移指南

### 数据迁移（如有需要）
如果旧系统中存在购买意向数据，需要手动处理：

```sql
-- 备份旧数据（可选）
CREATE TABLE purchase_intents_backup AS SELECT * FROM purchase_intents;

-- 删除购买意向表
DROP TABLE IF EXISTS purchase_intents;
```

**注意**：由于购买意向和订单的数据结构完全不同，无法自动迁移。建议：
1. 导出旧数据备份
2. 联系客户重新下单

## 📊 新旧对比

| 功能 | 旧系统（购买意向） | 新系统（订单管理） |
|------|-------------------|-------------------|
| 交易性质 | 意向登记 | 真实交易 |
| 库存管理 | 不扣减库存 | 下单扣减，取消恢复 |
| 订单状态 | 仅2个（处理中/已完成/已取消） | 6个状态流转 |
| 多商品 | ❌ 不支持 | ✅ 支持购物车批量下单 |
| 收藏功能 | ❌ 不支持 | ✅ 支持 |
| 订单详情 | 简单信息 | 完整信息（明细/金额/物流） |
| 商家控制 | 只能查看 | 完整订单流程管理 |
| 取消权限 | 无限制 | 客户发货前/商家完成前 |

## ✅ 升级后功能

### 客户端功能
- 浏览商品 → 添加到购物车 → 批量下单 → 查看订单 → 取消订单（发货前）
- 收藏商品功能
- 购物车管理（增删改查、转收藏、清空）

### 商家端功能
- 查看所有订单（支持按状态筛选）
- 订单流程管理：
  1. 确认订单（PENDING → CONFIRMED）
  2. 备货完成（CONFIRMED → PREPARING）
  3. 开始发货（PREPARING → SHIPPING）
  4. 完成交易（SHIPPING → COMPLETED）
- 取消订单（交易完成前）
